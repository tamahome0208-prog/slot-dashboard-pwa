# 自動ハーネス設計書

スロット管理ダッシュボードPWAの**勝率を継続的に高める**ための、3ロール自動改善ハーネス。

## ロール

| 役割 | 担当範囲 |
|---|---|
| **指示役 (PM)** | CEOとの対話／SNS・Web情報収集／改善案策定／修正役・検証役へのタスク発注／cycle_log更新 |
| **修正役 (Engineer)** | 指示役からの仕様を受けたコード実装／git commit & push |
| **検証・採点役 (QA)** | 4種KPI測定／コード回帰テスト／スコアシート発行／GOサイン or NG差し戻し判定 |
| **アナリスト (Analyst)** | royal_history.json (260+日) を用いた戦略バックテスト／統計分析 |

## KPI（勝率指標）

1. **実収支** — 記録された差枚×レート (`localStorage.records[]` から推定)
2. **AI推奨台 的中率** — `今日の狙い目` 推奨機種が実データで勝った割合
3. **バックテスト勝率** — royal_historyの過去ロジック再現スコア
4. **アプリ使用状況** — タブ滞在・記録回数（簡易テレメトリ）

## サイクル

### 日次（軽量・自動）
1. `scripts/daily_check.py` 実行
2. KPI更新／回帰テスト
3. 異常検知のみアラート

### 週次（大改修・自動）
1. **情報収集** (指示役): WebSearch/WebFetchで X / YouTube / みんレポ / 解析サイト
2. **提案策定** (指示役): backlog.json へ改善案を3-5件追加、優先度ランク付け
3. **並列実装** (修正役×N): 上位タスクを並列で実装
4. **検証** (QA役): 各ブランチで KPI & 回帰テスト
5. **デプロイ判定** (指示役): GO → git push, NG → backlog差し戻し
6. **記録** (指示役): cycle_log.json 更新／CEOへサマリ通知

## 完全自動モード

CEO承認なしでgit pushまで実行。ただし以下は例外で承認必須:
- 課金が発生する変更
- 個人情報を外部送信する変更
- 法的グレーな機能
